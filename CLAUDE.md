# BKI Website — Engineering Notes

Single-page React app for **BKI (Bimbingan Karya Ilmiah)** — a tutoring/coaching organization that manages coaches, students, parents, teams, classes, sessions, and reports.

## Stack

- **Frontend:** React 18 + Vite 8 + TypeScript (strict)
- **Routing:** React Router v6 (SPA)
- **Data:** TanStack Query v5 + Supabase JS v2
- **Auth:** Supabase Auth (email/password + Google OAuth)
- **Storage:** Supabase Storage (photos, session docs)
- **State:** Zustand (auth only)
- **Forms:** React Hook Form + Zod v4
- **UI:** Tailwind v3 + custom shadcn-style components (manually built, NOT installed via CLI)
- **Charts:** Recharts
- **Dates:** date-fns + date-fns-tz (display in WIB = Asia/Jakarta)
- **Backend logic:** Supabase Edge Functions (Deno) for Google Calendar / Drive / WhatsApp

## Schema — Authoritative

The single source of truth is the live Supabase schema. The full DDL is mirrored in `src/types/database.ts`. **Real column names, do not guess:**

- `profiles`: `auth_user_id`, `full_name`, `phone`, `photo_url`, `role`, `google_sub` — keyed by `id` (NOT `auth_user_id`). `auth_user_id` is the FK to `auth.users.id`.
- `coaches`, `students`, `parents`: each has its own `id` (PK) and `profile_id` (FK to `profiles.id`). Every join from teams/classes/sessions/tasks goes through THESE ids, never directly through `profiles.id`.
- `teams`: `team_code` (auto-generated by DB trigger), `research_title`, `coach_id` → `coaches.id`. Soft-deleted via `deleted_at`.
- `team_members`: links `team_id` ↔ `student_id` (students.id).
- `classes`: `coach_id` → `coaches.id`, `scheduled_at` (TIMESTAMPTZ — single field, no separate date/time), `duration_mins`, `media` enum.
- `class_teams`: junction; one class can serve multiple teams.
- `sessions`: `class_id` (nullable), `team_id`, `coach_id`, `session_date` (TIMESTAMPTZ), `duration_mins`. Soft-deleted.
- `session_student_reports`: scores are `score_discipline | score_activeness | score_communication | score_ethics | score_understanding` (1–10 smallint, NOT the Indonesian names).
- `session_docs`: `photo_url` (NOT `storage_path`), `sort_order`.
- `tasks`: `created_by_coach_id`, `team_id`, `assigned_student_id` (nullable = whole team), `submission_url`, `deadline`, `is_completed`.
- `task_refs`: per-task references (file/link).
- `parent_students`: links `parent_id` (parents.id) ↔ `student_id` (students.id), `monitor_phone`.
- `oauth_tokens`: per-profile Google tokens with `scope_level` ('basic' | 'drive_calendar'). **Never expose `refresh_token` to client.**
- `drive_links`: per-team Drive folders (`link_type`: team_report / team_docs / student_personal).
- `wa_notifications`: WhatsApp queue. Status: pending / sent / failed. Write via `queue_wa_notification()` DB function — not direct insert from client.
- `schools`: keyed by `npsn` (text PK).

### Enums

- `user_role`: coach | student | parent | admin
- `coach_division`: admin | research | paper | presentation | marketing | intern
- `media` (sessions/classes): online | offline
- `task_ref_type`: file | link
- `drive_link_type`: team_report | team_docs | student_personal
- `wa_status`: pending | sent | failed
- `oauth_scope_set`: basic | drive_calendar

## Auth Flow

1. User hits `/login` or `/register` → email or Google
2. Supabase returns session → `useAuthListener` (`src/hooks/useAuth.ts`) fires `SIGNED_IN`
3. We fetch `profiles WHERE auth_user_id = session.user.id`
4. **If no profile row**: redirect to `/onboarding/<role>` (role comes from `user_metadata.role` set at signup)
5. **If profile exists**: fetch role-specific row (`coaches` / `students` / `parents` keyed by `profile_id`). If missing, also onboarding.
6. Once full identity loaded → redirect to `/<role>` dashboard

`authStore` holds: `session`, `user`, `profile`, `coachId | studentId | parentId` (only one set, based on role), `loading`, `sessionRestored`.

## Security Invariants

- All DB writes go through Supabase RLS; never use service-role key on the client.
- `wa_notifications` inserts MUST use the `queue_wa_notification()` RPC, not raw insert.
- Google `refresh_token` lives server-side only (Edge Functions read/write `oauth_tokens`).
- Soft deletes: ALWAYS filter `WHERE deleted_at IS NULL` for `students`, `teams`, `sessions`.
- `team_code` is auto-generated by a DB trigger — never construct on client.
- All TIMESTAMPTZ stored UTC, displayed WIB via `formatWIB()` in `src/lib/utils.ts`.

## Conventions

- Imports use `@/` alias → `src/`.
- TanStack Query keys: `['<entity>', '<scope>', ...ids]` — e.g. `['sessions', 'coach', coachId]`.
- Always pass an **explicit generic** to `useQuery<RowType>` — Supabase's type inference can't resolve joined selects, so it returns `never` without the generic.
- Form schemas: `z.number().min(1)` + `register('field', { valueAsNumber: true })`. `z.coerce.number()` returns `unknown` in Zod v4 — avoid.
- Soft-deleted records are filtered at the query level, never in JS.
- Indonesian copy for user-facing strings. Code identifiers stay English.
- **Never `await` Supabase queries inside `onAuthStateChange` callback** — the callback holds the `navigator.locks` auth lock; awaited DB calls inside it deadlock. Set state synchronously in the callback, defer hydration with `queueMicrotask(() => void hydrate(...))`. See `src/hooks/useAuth.ts`.
- **PostgREST embeds via UNIQUE FK return single object or null**, NOT array. E.g. `profiles.select('id, parents(id)')` returns `parents: { id } | null` because `parents.profile_id` is UNIQUE. Don't `.length` it; null-check instead.
- **Silent error swallowing** is the #1 cause of empty dropdowns. Always destructure `{ data, error }` from Supabase calls and `if (error) throw error` (or surface it). Default to throwing in query fns; let TanStack Query expose the error to the UI.
- **RLS is per-action, not per-table.** Admin having SELECT on `parents`/`students` does NOT mean they have INSERT/DELETE. PostgREST returns HTTP 403 + Postgres error code `42501` ("insufficient_privilege") when RLS denies a write. If client-side admin mutations fail with 403, add `for all` policies (see DDL block at bottom).
- Admin user creation (auth + profile + role row) goes through Edge Function `admin-create-user` (uses `service_role`). Client never calls `supabase.auth.admin.*`.

## Design System

- **Font:** Plus Jakarta Sans (loaded in `index.html`).
- **Color tokens** (`tailwind.config.ts`):
  - `primary-50…950` — brand blue scale. `primary-950 = #0f2060` (deep editorial navy used for sidebar + hero overlays).
  - `surface-0…300` — neutrals (cards, page bg, borders).
  - `text-{primary, secondary, tertiary, inverse}` — semantic text colors.
  - `accent-{green, amber, red, purple, teal, rose}` — sparing accent palette for state.
  - Legacy `success | warning | danger` aliases retained.
- **Role accents** (gradient, used in sidebar + hero cards):
  - coach: `from-primary-500 to-primary-700`
  - student: `from-accent-teal to-primary-600`
  - parent: `from-accent-purple to-primary-700`
  - admin: `from-text-secondary to-primary-950`
- **Shadows:** `shadow-soft` (cards), `shadow-lift` (hover/popovers), `shadow-float` (modals), `shadow-inset-line` (active sidebar item).
- **Animations:** `animate-fade-slide-in` (page enter, used in `DashboardLayout`), `animate-slide-in-right` (slide-overs), `animate-fade-in`.
- **Aesthetic direction:** refined editorial minimalism — generous whitespace, soft cards, deep navy sidebar, restrained color use. NOT colorful — accents are for state, not decoration.

## Known Gotchas

- **Tailwind v3, not v4.** The shadcn CLI auto-detects v4 and breaks; all `ui/` components are hand-written using Radix primitives.
- `Database` type MUST be `type` (not `interface`), each table needs `Relationships: []`, schema needs `Views/Functions/CompositeTypes` — otherwise Supabase returns `never`.
- Lucide-react does not export `Chrome` — use `Globe` for the Google icon.
- `@apply border-border` is shadcn-CLI syntax that doesn't work without a CSS-variable color in `tailwind.config.ts`. We use `border-color: hsl(var(--border))` directly in `index.css`.
- Edge Functions must run on the Supabase project, not locally. Deploy via `supabase functions deploy <name>`.

## Required RLS Policies for Admin

If admin client-side mutations 403, run this in Supabase SQL editor (use `for all` so admin gets INSERT/SELECT/UPDATE/DELETE):

```sql
-- Run once per table. Pattern: admin profile lookup via auth.uid().
create policy "admin manage <table>"
on public.<table>
for all to authenticated
using   (exists (select 1 from public.profiles where auth_user_id = auth.uid() and role = 'admin'))
with check (exists (select 1 from public.profiles where auth_user_id = auth.uid() and role = 'admin'));
```

Tables that need this for admin features to work: `parents`, `students`, `parent_students`, `coaches`, `teams`, `team_members`, `class_teams`. (`profiles` typically already has admin SELECT.)
